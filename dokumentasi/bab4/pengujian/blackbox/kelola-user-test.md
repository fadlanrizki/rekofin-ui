# Pengujian Blackbox Fitur Kelola User

Dokumen ini berisi skenario pengujian blackbox untuk fitur kelola user pada aplikasi Rekofin UI.

| No  | Bentuk Pengujian                                                                                  | Hasil yang Diharapkan                                                                                                                           | Hasil Pengujian                                                                                        | Kesimpulan |
| --- | ------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------ | ---------- |
| 1   | Admin dengan token valid membuka halaman Kelola Pengguna                                          | Sistem menampilkan halaman Kelola Pengguna yang berisi field pencarian, tombol tambah pengguna, tabel data user, dan pagination.                | Berhasil sesuai hasil yang diharapkan. Seluruh komponen utama halaman tampil.                          | Valid      |
| 2   | Halaman Kelola Pengguna memuat data user dari API dengan sukses                                   | Sistem menampilkan daftar user beserta informasi nomor, nama pengguna, nama lengkap, role, tanggal dibuat, dan status aktif/nonaktif.           | Berhasil sesuai hasil yang diharapkan. Data user tampil sesuai respons API.                            | Valid      |
| 3   | Admin menekan Enter pada field pencarian dengan kata kunci username atau nama lengkap yang sesuai | Sistem memfilter data user sesuai kata kunci pencarian dan memperbarui isi tabel.                                                               | Berhasil sesuai hasil yang diharapkan. Hasil tabel berubah sesuai kata kunci pencarian.                | Valid      |
| 4   | Admin berpindah halaman pada pagination data user                                                 | Sistem menampilkan data user sesuai halaman yang dipilih dan memperbarui nomor/isi tabel berdasarkan data halaman tersebut.                     | Berhasil sesuai hasil yang diharapkan. Pagination menampilkan data halaman yang benar.                 | Valid      |
| 5   | Admin menekan tombol Pengguna untuk menambah user baru                                            | Sistem mengarahkan admin ke halaman form tambah user.                                                                                           | Berhasil sesuai hasil yang diharapkan. Halaman form tambah user berhasil dibuka.                       | Valid      |
| 6   | Admin mengisi seluruh field wajib pada form tambah user dengan data valid                         | Sistem memproses penyimpanan user baru, menampilkan notifikasi berhasil menambahkan data user, lalu mengarahkan kembali ke halaman daftar user. | Berhasil sesuai hasil yang diharapkan. User baru berhasil disimpan dan halaman kembali ke daftar user. | Valid      |
| 7   | Field Nama Lengkap dikosongkan pada form tambah user                                              | Sistem menampilkan pesan validasi Nama lengkap wajib diisi dan data tidak dikirim ke server.                                                    | Berhasil sesuai hasil yang diharapkan. Validasi pada field nama lengkap tampil.                        | Valid      |
| 8   | Field Username dikosongkan pada form tambah user                                                  | Sistem menampilkan pesan validasi Username wajib diisi dan data tidak dikirim ke server.                                                        | Berhasil sesuai hasil yang diharapkan. Validasi pada field username tampil.                            | Valid      |
| 9   | Field Email diisi dengan format tidak valid pada form tambah user                                 | Sistem menampilkan pesan validasi Email tidak valid dan data tidak dikirim ke server.                                                           | Berhasil sesuai hasil yang diharapkan. Validasi format email tampil.                                   | Valid      |
| 10  | Field Password dan Konfirmasi Password tidak sama pada form tambah user                           | Sistem menampilkan pesan validasi Password tidak cocok dan proses simpan dibatalkan.                                                            | Berhasil sesuai hasil yang diharapkan. Validasi konfirmasi password tampil.                            | Valid      |
| 11  | Field Role tidak dipilih pada form tambah user                                                    | Sistem menampilkan pesan validasi Role wajib diisi dan data tidak dikirim ke server.                                                            | Berhasil sesuai hasil yang diharapkan. Validasi role tampil.                                           | Valid      |
| 12  | Admin menambahkan user dengan username atau email yang sudah terdaftar                            | Sistem menolak penyimpanan dan menampilkan notifikasi gagal karena data user dengan username atau email tersebut sudah ada.                     | Berhasil sesuai hasil yang diharapkan. User duplikat tidak dapat disimpan.                             | Valid      |
| 13  | Admin mengaktifkan atau menonaktifkan status user melalui switch status                           | Sistem menampilkan dialog konfirmasi perubahan status sebelum status user diubah.                                                               | Berhasil sesuai hasil yang diharapkan. Dialog konfirmasi tampil saat switch status digunakan.          | Valid      |
| 14  | Admin mengonfirmasi perubahan status user pada dialog konfirmasi                                  | Sistem mengubah status aktif/nonaktif user, menampilkan notifikasi berhasil, lalu memperbarui daftar user.                                      | Berhasil sesuai hasil yang diharapkan. Status user berubah dan data tabel diperbarui.                  | Valid      |
| 15  | Admin membatalkan dialog konfirmasi perubahan status user                                         | Sistem tidak mengubah status user dan daftar user tetap seperti sebelumnya.                                                                     | Berhasil sesuai hasil yang diharapkan. Tidak ada perubahan status setelah proses dibatalkan.           | Valid      |
| 16  | Pengguna tanpa token valid atau bukan role ADMIN mengakses fitur Kelola Pengguna                  | Sistem menolak akses ke halaman/admin endpoint kelola user dan mengarahkan pengguna ke login atau meminta autentikasi ulang.                    | Berhasil sesuai hasil yang diharapkan. Fitur hanya dapat diakses oleh admin yang valid.                | Valid      |
| 17  | Terjadi gangguan server atau jaringan saat mengambil daftar user                                  | Halaman tetap stabil, proses loading berhenti, dan data tidak menyebabkan aplikasi crash.                                                       | Berhasil sesuai hasil yang diharapkan. Aplikasi tetap stabil saat terjadi error pengambilan data user. | Valid      |
